# 通用剪辑 Skill 的能力需求与结果交接

本合同适用于所有原子与复杂 Skill。Skill 说明要完成什么、输入和结果如何核对；运行 Agent 选择当前可用的 ChatCut、剪映、其他编辑器工具、MCP、CLI 或本地执行器。Skill 提到 `editing_runtime.py`、SQLite 或 FFmpeg，只表示本库的一种可选实现，不是调用 Skill 的前置条件。具体工具授权、登录、密钥、模型、调度和费用由运行 Agent 按用户任务处理。

## 执行前：把意图映射到能力

读取当前 Skill 与相应操作合同，提取明确对象、源/输出时间坐标、参数、预期产物、必须保留的内容及允许修改范围。检查现有工具能否实际读取对象、执行操作并提供足以核对结果的读回能力。工具名称不必与原子 ID 相同：

| Skill 能力 | 可接受的工具动作 | 不可代替的条件 |
|---|---|---|
| 素材观察、探测、抽帧 | 编辑器素材查询、媒体探测器、帧导出 | 来源身份和时间坐标可追溯；抽帧不等于内容判断 |
| 片段、字幕、音轨或画面参数修改 | 编辑器时间线 API、可核验 CLI、本库本地 runtime | 明确对象、参数、目标范围；写前读当前修订标识 |
| 预览、渲染、导出、技术检查 | 编辑器导出、媒体工具、本库本地 runtime | 实际输出读回与当前作品/版本绑定；技术通过不等于看听通过 |
| 作品续改、局部采纳与恢复 | 编辑器项目历史/API、Agent 维护的同作版本记录、本库 Work | 同一作品身份、最新状态、非目标保持、冲突拒绝和可恢复记录 |

缺少必要读取、写入或读回能力时，准确报告 `capability-unavailable`、缺少的动作/字段、受影响交付、已完成的独立部分和恢复条件。不要因本库本地 runtime 不可用就断言其他工具也不可用，也不要把未见过的工具能力说成已支持。需要字节级冻结的操作若工具无法提供字节或可信摘要，须把该检查标为 `not-verifiable`；不能以稳定素材 ID 伪造 SHA-256。

## 交接给执行工具

Agent 传递与当前工具相符的参数，至少保留：任务/操作 ID、目标作品与当前修订标识、素材身份及来源、源时间和输出时间的坐标约定、显式参数、允许修改与保护范围、预期产物。素材身份可以是已读字节的 SHA-256，也可以是编辑器给出的稳定资产 ID 加项目/修订标识；后一种须说明字节哈希未知。权限或模型配置不写入 Skill 请求或结果记录。

[本地操作合同](operation-contract.md)的严格路径、SHA、JSON 字段仅约束选择 `editing_runtime.py` 时的请求。使用其他工具时保留上述语义，不为凑本地 schema 导出或伪造 SQLite、媒体文件、哈希或宿主版本。

## 写入结果不确定时：先读回同一作品

外部编辑器写入前，在本次已有操作记录中保留目标作品、写前修订、目标字段的原值与期望值、允许范围和非目标保护项。超时、取消、连接中断或部分结果不证明写入已回滚；保存原操作 ID、请求与返回，不直接重放，也不另建同作执行副本。若工具有任务查询能力，查询原操作；随后读回同一作品的当前修订、目标字段及相关非目标范围，核对实际保存状态。稳定对象 ID 不能替代字段值或修订，取消请求已送达也不等于取消已生效。

在现有报告中区分以下结果；这是读回判定，不要求工具新增状态字段或迁入本库 schema：

| 读回判定 | 需要的依据 | 后续动作 |
|---|---|---|
| 已应用 | 有可核实的已完成终态/提交记录，可确认该次写入已结束，且同作目标字段确已达到本次期望；非目标保持另行核验 | 不重复提交；记录实际修订，继续相应结果复核。非目标异常或后来手改仍须单独处理，不能据此宣称保护通过 |
| 未应用 | 已确认原操作不会继续写入，且最新读回与历史未见本次目标变化 | 基于最新修订重新判断原授权与范围；只有安全写入条件仍成立才重新准备操作，不能原样盲重放 |
| 部分应用 | 可定位已写入的目标字段及未写入/冲突字段，保留各自实际值与修订依据 | 先确定原操作是否仍可能写入；保留已应用部分和后来手改，仅对明确缺项形成受限续接或恢复方案，不重放整批 |
| 未知 | 无法可靠读回、身份/终态不明，或原操作仍可能继续写入 | 保留请求与读回缺口，暂停该写入的重试/采用，继续可独立完成的部分；明确恢复所需的原任务终态、同作读回或并发保护条件 |

单次快照仍为旧值不能证明“未应用”，目标值碰巧相同也不能独自证明该次操作已完成。发现后来手改时，以最新作品为保持项基线，按已有局部采用/恢复规则处理，不能用写前快照覆盖最新状态。原操作仍在运行或终态未知时，不启动相互竞争的修复写入；查询、读回与停止继续写入的确认分别记录。

没有安全并发控制或必要读回能力时，只阻塞受影响的原作写入/采用；可按现有授权交付隔离候选或可编辑计划，并说明该候选尚未采用到原作、已知状态与恢复条件。此前未知/部分应用的原操作仍保留相应记录，不能改称原作未变。隔离候选须有明确基线和独立目标，不能覆盖原工程或宣称已与原作同步。不得为此强制转换成 SQLite。工具一旦具备所需条件且原授权仍适用，即沿最新作品续接，无需为常规恢复新增批准环节。

## 执行后：读回、复核和采用

记录实际工具及可核实版本、输入身份、操作 ID、执行状态、项目/修订前后标识、改动对象与范围、输出标识或文件、读回证据、未能核实的项目。工具返回 success 只证明其响应；如可读回，应重读当前项目/输出，核对目标改动和非目标保持。读回无法做到时，标明限制，不声称已完成局部保护或实际交付。

复杂 Skill 评审候选后再采用。局部采纳须先读当前作品，比较候选基线与当前修订，写入明确的目标范围，保留用户手改及保护项；冲突时停下重读并重新判断，不只替换版本号。采用后再次读回，记录同一作品的新修订和回退点。模型生成候选由运行 Agent 提供实际来源/任务/资产身份；本 Skill 负责评审它是否适合当前作品、纳入时间线及后续修改，模型选择/API费用不是 Skill 依赖。

结构/技术、内容、完整看听、目标编辑器工程和独立评审分别记录证据。没有相应证据就保留 `not-run` 或 `not-verifiable`，不提升为通过。 本次交付结论由复杂层按[既有交付报告规则](editorial-contract.md#本次交付报告)汇总；原子技术回执及其未认证标记保留原样，不能据此跳过检查，也不把库级真人验收变成每次交付的前置。
