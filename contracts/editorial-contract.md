# 复杂 Skill 决策与交付合同 v1

本合同按[通用能力交接](capability-handoff.md)由运行 Agent 映射到当前实际可用的编辑工具；本库 Work/SQLite 与本地 runtime 是可选执行实现，不是所有作品必须迁入的第二份工程。若已有编辑器项目，沿用其作品身份、版本及历史，核实际改动与读回能力。

复杂层承担创作判断；原子层不得补做未显式给出的选择。

## 工作对象与模式

首先从 Query 和当前作品提取：目标对象、交付模式、时长/画幅、必须保留/禁止改变、素材范围、剧透/事实约束、风格与目标观众。保留用户原话与已解析约束，不要求用户重复填写。

- ANALYZE：只交付有证据的理解或选段，不自动写旁白/生成成片。
- PLAN：交付主线、风格和声画计划，不伪造媒体产物。
- EDITABLE：交付可继续修改的计划/工程；当前 JSON 计划不等于已在目标 NLE 打开验收。
- PRODUCE：持续到实际成片、字幕和必要验证；依赖未满足时保留受影响阶段的阻塞。
- REVISION：基于最新作品和选区修改；先读当前状态，未点名区域默认保持。

本地已有作品可通过 [作品合同](work-contract.md) 保存当前文档和追加版本历史。候选范围校验、版本冲突拒绝、局部采用与整版恢复的边界由该合同实现；这是本地JSON/SQLite能力，不等于原生编辑器自动同步。

当前任务明确要求持续保留的原话、条件或内容依赖，可按该合同登记为版本内 evidence_protection。上层负责判断声明的内容和真实依据，原子只验证显式区间、来源与依赖；不要把可随请求一起删除的单次 evidence-map 当作跨轮保护。普通修改继承声明，必要的承载映射调整用显式范围并重验。用户明确改变保护意图时单独 set-protection 记录依据，不为达到时长或绕过失败自行撤销；调用方的 author 字段不是批准凭证。

精确操作 Query 可以直接调用原子 Skill。含主观判断的短指令仍由场景复杂 Skill 或修改入口处理。发生跨场景组合时保留一个 TaskSpec 和作品身份，不各建一条互不相干的时间线。

## 决策文件

TaskSpec 保存 Query、模式、目标、约束与允许修改范围。SourceManifest 由 media-inspect 建立；Observation 包含源范围、内容观察和不确定性。EditorialPlan 至少写：

- 观众承诺、主视角、结构、风格 ID/版本及所用变化项。
- 事件与人物证据，源时间/故事时间/揭示顺序的必要映射。
- 每个 beat 的目标、状态变化、选段与淘汰原因。
- 镜头的证据/上下文/反应/转场用途；主要声音所有者。
- 必须完整保留的句子、动作和沉默，以及剧透边界。

只记录可审阅的决定和依据，不要求暴露内部推理过程。编译到 ExecutionPlan 时使用真实源 ID、合法时间与明确参数；不可把“找最感人的画面”这样的任务留在原子操作参数里。

## 风格选择与扩展

先读索引定位可能适用的家族，再加载与当前素材相关的风格卡。用户指定的风格/约束最高优先；不合适的预设可修改或新建，风格数量不设上限。每个新风格必须写清与最近邻的实质差异和适用证据，不能给同一规则换名字凑数。

风格卡中的示例都是结构示例，不是源片事实。采用的具体镜头和旁白必须重新绑定当前素材。风格来源可为已归档方法或原创综合；不得把来源支持通用方法说成来源验证了每种原创风格的实际效果。

## 验证与恢复

按照阶段依赖失效：素材/转写变化 → 相应理解与计划；风格/主线变化 → 选段和声画方案；文字变化 → 对应配音及下游；局部切点 → 字幕映射、渲染和受影响验收。不可将旧 QC 绑定新视频。

输出技术 checks、内容核验、最终画面复核、实际听检各自范围/方法/问题/证据。缺实际观看/听检就标未执行；Agent 自评风格成立不构成独立盲评。可核实的硬错误必须修复，主观意见保留差异，不套用一个分数裁决所有审美。

## 本次交付报告

沿用当前复杂 Skill 的结果报告，不另建交付 schema。先写本次 Query 的实际交付模式、范围及产物身份，再并列技术检查、内容核验、最终画面/听检、输出读回、未决问题及其影响；引用原始回执与评审记录及其范围，不把不同版本的通过项拼成当前作品已通过。身份使用实际可核文件哈希或编辑器作品/修订/输出 ID，并说明字节身份未知的限制；相同文件名不构成同一产物。

技术 QC 的 `DEGRADED`、`content_review: NOT_RUN` 等标记，以及 work-delivery 的 `publishable:false`，保留在原回执中，表示该技术操作未认证内容、看听或可发布性。复杂层可以依据同一实际产物的后续证据，在现有报告中给出本次交付结论，不回写原回执、不伪造技术认证，也不把 `publishable:false` 自行改成 true。原子 `SUCCEEDED` 同样不能单独授予本次交付通过。

沿用结果报告的 PASSED / DEGRADED / BLOCKED 口径并写明范围：当前模式必要检查齐全且目标成立才 PASSED；必要内容、看听或读回未做/无法核实时为 DEGRADED，说明只能交已完成部分与恢复条件；有可核实的技术、事实或保护约束错误时，受影响交付为 BLOCKED，修复后再验证。未决问题若不影响本次有限交付，说明其范围；不能省去用户要求来改变完成口径。原报告及失败记录保留，产物变化后按实际影响补证。

普通成片交付核实际技术、内容、完整画面/听检和输出读回；纯 SRT、纪要或分析交付按实际文本目标核来源、语义、文件/对象读回和所需可编辑性，不凭空要求音视频制作，也不声称未做的声音/画面检查。没有真人修改历史不阻止这类本次交付，不为通过制造 `author:human` 或虚构修改事件。库级 D6/G5 的真人同作续编与独立评测仍单独验收；若用户本次确实要求人工作品接管、局部修改或恢复，则相应最新状态、非目标保持、冲突和恢复证据仍必需。只有明确承诺目标编辑器原生工程时，才追加对应打开、修改、导出与重开证据；本次交付判断不授予素材发行许可或库级发布通过。

没有授权素材或服务时，不虚构源片和模型结果；继续可独立完成的阶段。昂贵操作复用已有授权，但授权并不代替可用凭据和任务状态核对。
