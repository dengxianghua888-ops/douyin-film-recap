# 影视故事理解协议

## 1. 为什么场景摘要不够

“男人走进办公室，女人哭了”只描述画面。

影视解说还需要知道：

- 两人是谁
- 他们此前发生了什么
- 谁想得到什么
- 谁掌握信息
- 谁误解了谁
- 这次进入改变了什么
- 观众现在是否应该知道真相
- 这段表演为何比一句摘要更重要

因此，系统必须从场景表升级为有证据的故事状态。

## 2. 四条时间轴

### `source_time`

原始视频时间。

### `story_time`

事件在虚构世界中真正发生的顺序。

### `reveal_time`

原片向观众揭示信息的顺序。

### `output_time`

解说成片中的时间。

映射：

```text
source_time
→ story_event
→ audience_knowledge
→ recap_reveal_decision
→ output_time
```

非线性影片、悬疑片、回忆、梦境和身份反转必须显式维护四条时间轴。

## 3. 人物注册表

```json
{
  "id": "c01",
  "display_name": "林默",
  "aliases": ["男主", "林警官"],
  "temporary_name": false,
  "visual_signatures": ["黑色风衣", "左眉疤痕"],
  "voice_cluster": null,
  "first_seen": {"source_id": "s01", "time": 12.4},
  "relationships": [
    {"target": "c02", "type": "partner", "confidence": 0.88}
  ],
  "evidence": [],
  "confidence": 0.91
}
```

规则：

- 名字不确定时使用稳定临时 ID，不要每个场景重新命名。
- 不因服装变化轻易拆成新角色。
- 不因相似脸轻易合并。
- 年轻 / 年老、伪装、梦境版本要保留映射。
- 人工或外部资料修正必须留下来源。

## 4. 故事事件

```json
{
  "id": "e018",
  "story_order": 21,
  "source_spans": [
    {"source_id": "s01", "start": 133.2, "end": 148.0}
  ],
  "participants": ["c01", "c03"],
  "goal_before": {"c01": "隐藏身份"},
  "event": "对方拿出旧照片质问",
  "state_change": {
    "knowledge": "怀疑 -> 确认",
    "relationship": "合作 -> 对立",
    "risk": "低 -> 高"
  },
  "causes": ["e012"],
  "consequences": ["e019"],
  "evidence": [],
  "confidence": 0.86
}
```

每个保留 Beat 至少改变一项：

- 知识
- 权力
- 关系
- 目标
- 风险
- 情绪

没有变化的场景通常只适合作为 VO 压缩素材或过渡。

## 5. 观众知识

```json
{
  "event_id": "e018",
  "audience_knows_before": ["c03 怀疑 c01"],
  "audience_knows_after": ["c03 确认 c01 的真实身份"],
  "character_beliefs": {
    "c01": ["秘密已暴露"],
    "c03": ["c01 曾欺骗自己"]
  },
  "reveal_sensitivity": "high",
  "allow_prepose": false
}
```

用途：

- 防止提前剧透
- 防止把观众知道的信息误写成角色知道
- 防止把角色误解写成客观事实
- 决定钩子是否可以前置

## 6. 层级理解

长片不能一次平铺给模型。

推荐：

1. Scene Unit：6–18 秒
2. Sequence：1–5 分钟
3. Act / Episode Arc：10–40 分钟
4. Global Story：整片或多集

每层输出压缩状态，不只是摘要。

### Scene Unit

- 画面事实
- 对白事实
- 当前人物
- 局部情绪
- 高光信号
- 不确定点

### Sequence

- 目标
- 冲突
- 结果
- 人物关系变化
- 关键证据
- 候选高光

### Global Story

- 主线
- 支线
- 人物弧线
- 故事顺序
- 揭示顺序
- 主题
- 类型
- 终局

## 7. 证据等级

### A：直接证据

- 画面明确显示
- 原声直接说出
- 字幕和画面一致
- 多个场景相互印证

### B：强推断

- 行为与上下文高度一致
- 后续情节验证
- 人物关系有多个证据

### C：弱推断

- 单个表情
- 模糊台词
- 仅根据类型套路
- 外部简介但源片未出现

C 级不能写成确定事实。

## 8. 外部资料

影片简介、演员表和百科可以帮助：

- 识别人物名字
- 确认剧集信息
- 解释历史背景

但不能：

- 覆盖上传版本里的实际剧情
- 为源片没有出现的事件补证
- 把影评观点写成人物动机

所有外部信息标为 `external_context`。

## 9. 不可靠叙事

发现以下信号时提高风险：

- 闪回与现实没有明确标记
- 梦境
- 同一事件有多个版本
- 角色说谎
- 画外音与画面冲突
- 时间循环
- 身份互换
- 双胞胎 / 相似角色
- 记忆缺失
- 旁观者误解

必须把“客观事件”和“角色叙述”分开。

## 10. 故事置信度

建议维度：

- 角色一致性
- 关系一致性
- 事件顺序
- 因果链
- 揭示顺序
- 关键反转
- 结局
- 字幕可靠性

任一关键维度低于阈值，不应直接输出 `PASSED`。
