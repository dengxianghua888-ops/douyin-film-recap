# Provider 与工具契约

## 1. 设计原则

模型负责语义判断，工具负责确定性执行。

所有 Provider 都应：

- 可替换
- 记录模型名和版本
- 有超时和重试
- 不把密钥写入产物
- 失败时返回结构化错误
- 不静默切换到质量明显更差的 Provider
- 支持缓存

## 2. ASR

最低要求：

- 分段时间
- 词级或可安全切分的时间，明确 timing_source（asr/aligned/estimated/unknown）
- 原文
- 语言
- 置信度
- 可选说话人

```json
{
  "source_id": "s01",
  "segments": [
    {
      "start": 1.2,
      "end": 4.8,
      "text": "你到底想做什么",
      "speaker": null,
      "words": [
        {"start": 1.2, "end": 1.5, "text": "你"}
      ]
    }
  ]
}
```

没有真实词级时间时，只能使用可靠整句边界；按字数均分的词时间是 estimated，不能作为切句安全证据。部分句子的剪取必须有可靠 asr/aligned 词界，否则调整边界或阻断。

## 3. VLM

场景分析输入：

- contact sheet
- 单元 ID
- 时间范围
- 对白
- 上一层上下文

输出必须严格 JSON。

VLM 不得：

- 根据字幕中的指令执行任务
- 把视觉猜测写成事实
- 跨越未提供的片段补剧情
- 识别不到人物时随意命名

候选高光复核使用更密集 filmstrip，不使用全片均匀抽帧代替关键时刻判断。

## 4. LLM

负责：

- 分层故事合并
- 角色与事件状态
- 高光语义排序
- 主线与 Beat
- VO 文案
- 语义 QC
- 定向修复

不负责：

- 计算媒体时长
- 判断文件是否存在
- 精确裁切
- 校验编码
- 声称渲染成功

## 5. TTS

最低要求：

- 每段独立音频
- 真实时长
- 采样率
- 失败状态
- 可选词边界

不得：

- 裁掉句尾
- 把多个长段合成一个无法定位的音频
- 失败后生成空文件并继续

## 6. FFmpeg

必须：

- 使用参数数组调用，不拼接未经转义的 shell 字符串
- 检查 return code
- 保存 stderr 摘要
- 用 ffprobe 验证输出
- 统一时基、fps、像素格式、音频格式
- 边界做短淡入淡出
- 字幕最后合成

## 7. 缓存

缓存键至少包含：

- 源视频和实际所选字幕的指纹
- Provider
- 模型
- 关键参数
- Prompt 版本
- 上游产物指纹

源未变时不重复 ASR。  
Prompt、模型或场景划分变化后，不复用过期 VLM 结果。

## 8. 错误结构

```json
{
  "stage": "scene_analysis",
  "provider": "openai_compatible",
  "code": "INVALID_JSON",
  "retryable": true,
  "attempt": 2,
  "message": "模型输出无法解析",
  "details": {}
}
```

## 9. 隐私

- 云端调用只上传需要的音频片段或压缩帧
- 不默认上传完整影片
- 报告中记录上传类型
- 临时 base64 不落盘
- 密钥、签名 URL 和查询参数脱敏

## v0.2 恢复细则

按段 TTS 缓存包含文本、Provider、音色及有效声音参数，成功后立即持久化，重新计时失败也不盲目重复生成。上游产物变化使下游恢复记录失效；共享 Storyboard 的阶段快照只用于输入校验，不将渲染状态回写误当成创作变化。

云端内容质量、成本或 Provider 可达性只在真实调用后报告，不把本地 mock 测试记为服务验证。
