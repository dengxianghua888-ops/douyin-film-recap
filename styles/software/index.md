# 软件教程与演示风格库

18 个初始方向，不设数量上限；每张卡必须以独特信息组织机制和真实效果支撑。当前全部 authored-unvalidated。按用户任务加载主风格，其他只在有用时组合。

| 风格 | 适用 | 区别 |
|---|---|---|
| [首次上手带练](guided-first-run.md) | 初学者第一次完成一个明确软件任务 | 与问题解决相比面向尚无操作经验，入口与基础定义保留更多 |
| [单问题解决](task-resolution.md) | 用户知道软件，但只想完成一个任务 | 与首次上手不同可略过已知入口；与排错不同目标是完成任务而非诊断根因 |
| [证据排错](diagnose-repair.md) | 有真实错误或异常反馈，素材包含诊断和复验 | 与单问题解决相比诊断依据是主线，不只是步骤列表 |
| [熟手技巧卡](expert-shortcut.md) | 受众已熟悉软件，素材展示一个有条件的快捷方法 | 与键盘流不同聚焦一项技巧，不组织完整无鼠标流程 |
| [概念落到操作](concept-action.md) | 软件设置涉及难懂概念，需要解释其作用 | 与首次上手相比目标是理解机制，不必覆盖全入门流程 |
| [证据型产品演示](evidence-demo.md) | 已有真实任务与运行结果，需要让观众相信能力 | 与案例故事相比证据检验优先，戏剧起伏可以很弱 |
| [改前改后解释](before-after.md) | 同一输入有可比的初始与修改后结果 | 与条件对比相比看同一作品的变化，不是挑选不同工具 |
| [同条件方案对比](controlled-comparison.md) | 两种操作方式或工具各有适用条件 | 与改前改后相比比较独立方案，而非一次修改 |
| [静音可跟做](silent-walkthrough.md) | 观看环境不适合声音，动作和文字足以解释 | 与首次上手可组合；区别在全部必要信息能从画面获得 |
| [复杂界面分层讲解](progressive-reveal.md) | 复杂表格/编辑器包含多个关联区域 | 与概念落操作相比主解空间/区域关联而非抽象参数机制 |
| [迁移与替代操作](migration-guide.md) | 用户从旧工具/旧版本迁移，有惯性路径 | 与版本更新导览相比重在用户迁移任务与资产保持 |
| [失败边界演示](failure-boundaries.md) | 功能容易被误解为无条件成功，有可复现失败条件 | 与证据排错相比预先解释产品边界，非解决未知原因 |
| [版本变化导览](release-delta.md) | 已有用户关心版本更新对现有工作方式的影响 | 与迁移指南相比重点是差异认知，不要求完整资产迁移 |
| [阅读优先教学](readable-deliberate.md) | 文字密集或目标观众需要更长定位和理解时间 | 与首次上手不同专注可读与认知负荷，适用于专业观众 |
| [键盘连续操作流](keyboard-workflow.md) | 受众熟悉软件，要求展示可执行快捷键流程 | 与熟手技巧卡相比是多步连续流程，重点是焦点和模式一致 |
| [单案例产品故事](case-story.md) | 一个真实使用任务有明确阻碍和结果 | 与证据型演示相比强调任务经历与选择，但证明要求不降低 |
| [判断过程演示](decision-trace.md) | 工具或 Agent 的价值在依据证据选择下一步 | 与证据型演示相比核心是决策随证据改变，不仅证明能完成 |
| [试做与回退教学](reversible-exploration.md) | 创作软件需要试效果、比较并撤销，用户关注控制感 | 与前后对比相比回退/局部采用本身就是教学目标 |

评测与兼容规则见 [教程评测](../../workflows/raven-software-tutorial/references/evaluation.md)。
