# 单字幕轨的重叠话轮

当两人同时说话而宿主只支持单个非重叠字幕序列时，先保留每位说话人的独立源词区间，再由复杂层明确显示窗口。不要直接把第二人的短回应附在第一人的整句上：AMI 候选曾让 A 的 Mm-hmm 随 B 的句子提前3.13秒显示。

先核对文字、说话人及时间来源。AMI 的文字是人工转写，逐词时间是自动强制对齐；源词时间仅为观察依据，不是听检或口型真值。没有更强声学证据时保留这个限制，不能把修正显示窗口写成同步验收。

## 决策和操作分工

- 本层确定分句、归属、显示停留、行顺序及阅读负担；短应答可利用空隙延长，但不得提前表示已经回应。对齐不确定时先复核，不用任意延时伪装修复。
- [partition_speaker_cues.py](../scripts/partition_speaker_cues.py) 接收显式整数帧区间，按所有开始/结束点分割，每个半开区间只显示当时活跃的说话人文本。工具不转写、不选取词、不决定停留时间、不写作品数据库。
- 同一说话人的输入窗口重叠时拒绝，让调用方解决分句/窗口冲突；不静默丢词。显示顺序必须明确，不能由音量或字母顺序推断。
- 输出事件写回当前作品字幕候选，删除被替代的旧cue；通过 timeline-revise 限制修改范围，再按真实最新版本提交。保留未选字幕、署名、已校对文字、画面、音轨和已有修改。

## 输入及调用

JSON 顶层只有 `cues` 和 `display_order`。每个 cue 必须包含：`id`、`speaker`、`text`、`speech_start_frame`、`speech_end_frame`、`display_start_frame`、`display_end_frame`。所有区间共享同一输出时钟；`display_order` 包含每个 cue ID 一次。调用方负责源到输出映射、帧率与帧量化，不能混用源帧和输出帧。保留原始秒数和量化决定以供追溯。

```bash
python3 scripts/partition_speaker_cues.py request.json partition.json
```

输出 `events` 包含 `start_frame`、`end_frame`、`source_cue_ids`、`text`。输出文件使用独占创建，不覆盖历史证据。适配WorkDocument时除以实际帧率，并锚定正确片段；不得把25fps例子当通用默认。

例如 B 的窗口[0,112)，A的源窗口[79,84)、显式显示窗口[79,104)，行顺序B/A，结果为[0,79) B、[79,104) B+A、[104,112) B。A不会被提前带到第0帧，也不会自动延长到B句末。若3人重叠，工具可保留3行；这不证明最终画面读得完，本层仍须调整呈现方式。

## 实际检查

在每个回应出现前、出现时及结束后查看最终字幕和机位关系；核对所有输出帧的活跃ID与显式窗口一致，同时完整看听确认实际源发声。分割后行数改变可能让主句上下移动，应观察合成画面；无法接受时选择可用的固定字幕层布局，不靠提前显示回应来稳定版式。

本地 `evals/runs/interview-overlap-repair-01/` 记录对既有三份作品的有限修复。只证明明确窗口、同作保护和产物检查覆盖到的范围，不提升独立风格、听检或宿主验收状态。
