# 跨候选的三方局部采用

用于“采用旧候选的开头和字号，保留当前音量、字幕手改和后半段”。复杂层先把用户授权拆成稳定对象上的字段或结构操作；不要按整个旧片段、样式或作品覆盖。以下协议适用于可读写项目的 Agent，不要求其使用本库 SQLite。

## 输入与可核身份

- **base**：donor 与 latest 分叉前的共同基线。用项目历史、派生记录或宿主版本链证明两侧都从它出发；同名文件、相同时间戳或调用方自报祖先不足以证明。
- **donor**：用户选中的旧候选或历史版本，提供要采用的值、对象或顺序。
- **latest**：写入前重新读取的当前项目。保留项与提交前条件都以它为准，不以 donor 或 base 代替。
- 三份快照均记录项目身份、原生修订标识或可核内容摘要、对象稳定 ID、对象及字段值、对象顺序，以及来源关系的证据。修订标识可以是宿主版本、提交 ID、ETag 或内容哈希；不必伪造 Work token。无共同基线、身份无法校验、对象 ID 不稳定、宿主无法表达或保护所需字段时，停止采用并报告限制。压平 MP4 不能冒充有独立字幕/音轨的项目。
- 写入采用宿主支持的条件更新或 compare-and-swap。写前再次核对 latest 修订；若已变化，重新读取、三方比较、校验和生成候选，不能只换修订标识。没有原子条件写入能力时，不能宣称并发安全；只保留候选供人工导入/复核。

## 明确选择和比较

选择单位为稳定对象 ID 上的字段路径，或显式的插入、删除、移动操作。列表不得用位置索引代表身份。路径每层需在快照中唯一定位；同 ID 重复、未知字段、无法读取的值均拒绝。每个选择记录用户意图、目标值来源、受影响字段/依赖范围及必要的冲突取舍。未选字段和对象直接从 latest 复制；不以 donor 的完整对象填补缺口。

对一个已存在的选中字段，分别读 base 值 B、donor 值 D、latest 值 L。L=B 时可取 D；L=D 时已满足，无需写；L 与 B、D 均不同是冲突，保留 latest 并等待有依据的字段级取舍。即使 D=B（明确恢复旧值），L 的后续修改仍是冲突。取舍只能来自用户本轮明确要求或已有授权：选择 donor 覆盖此字段，或 latest 保留此字段；不能因脚本支持 `resolution` 就自动填。任一选中字段未解决时，整份候选标为 CONFLICT，不部分提交。

对象存在性也参与三方比较，使用明确的“缺失”状态，不把 null、空串和删除混为一谈：

| 选中操作 | 可直接准备 | 必须冲突/拒绝 |
|---|---|---|
| donor 删除 base 已有对象 | latest 中该对象的字段、父级、锚点和相对位置均仍与 base 一致，且引用、保护和相邻时序能随明确范围处理；或 latest 也已删除则无需写 | latest 已修改或移动该对象、改动其父级/锚点，或新增对它的依赖；删除影响未授权资源。例如 base=[A,B]、donor 删除 A、latest=[B,A] 时必须报冲突 |
| donor 插入 base 没有的稳定 ID | latest 没有该 ID，全部必填字段和插入位置/依赖已明确；或 latest 有同一对象且位置相同则无需写 | latest 已占该 ID 但内容/位置不同；来源或锚点不完整 |
| donor 修改/恢复 base 已有对象 | latest 仍有该 ID，并逐字段按 B/D/L 比较 | latest 已删除该 ID；不得因旧候选而复活 |
| donor 移动/重排对象 | 选中移动对象及前后稳定锚点明确，latest 中锚点存在，且 latest 对这些对象的位置未作不同移动；其余对象原有相对顺序保留 | 锚点已删除、目标位置歧义、latest 对同一位置另有移动，或会重排未授权对象 |

插入、删除、移动按对象及其关联字段作为一个结构操作处理。先核对成员集合，再核对稳定锚点和相对次序；有多个可行插入位且用户未指定时不猜。删除不能以 donor 的旧快照顺便删除 latest 新增对象；插入不能覆盖 latest 同 ID 对象；移动不能默默改动未选对象的相对次序。字幕锚点、音轨、叠层、保护单元、时长、衔接及冻结位置都要通过当前项目能力再校验。范围与冲突检查成立仅证明结构安全，不证明画面、听感或叙事效果。

## 候选、提交与验证

先输出差异：每项的 B/D/L、采用或保留决定、冲突、结构依赖及 latest 修订绑定。候选从 latest 拷贝，仅修改已授权且无冲突的字段/对象/顺序。提交前由宿主或本地执行器复核编辑约束并作条件写入；失败保留回执和当前项目，不将“候选已生成”算作采用。提交后重新读取当前状态，逐项证明选中值/顺序已落地、未选音量/字幕/备注和删除状态仍保留，再做相邻声画、时长、字幕与实际媒体检查。用户只要求候选时停在可审阅候选。

## 可选本地 Work 实现

[prepare_field_adoption.py](../scripts/prepare_field_adoption.py)仅在三份输入都是本库 `work-version read` 的 WorkState 时使用。它核对 document_sha256 与内容一致、version 与所给 work_id/sequence/摘要形成的 token 自洽；不能由这些自报字段证明真实项目身份、当前修订或共同祖先，调用方须从作品历史独立核实。它只支持已存在的标量叶字段，不处理插入、删除、整对象或重排。后几类先按上面通用规则由复杂层形成显式候选，再交 [timeline-revise](../../../atomic/timeline-revise/SKILL.md) 校验范围和依赖；不可把标量脚本的 PREPARED 当作结构操作通过。非 SQLite 项目直接用宿主的稳定对象与修订标识遵循同一规则，无须转换成 WorkState。

本地脚本输入固定为 `base/latest/donor/selections`；选中字段示例：

```json
{"selections":[
  {"path":["plan","clips",{"id":"c1"},"start"]},
  {"path":["plan","clips",{"id":"c1"},"end"]},
  {"path":["caption_style","font_size"]}
]}
```

例如 latest 后来把增益改为 -2 dB、手改字幕、删去旁白，donor 只提供开头源范围和字号：候选只更新这三个选中字段，保留 latest 增益、字幕、删除状态。若 latest 也把开头改成另一范围，则开头字段报冲突；不能用旧候选整版覆盖，也不能借旧旁白对象把删除撤销。需要人工选择覆盖时，仅对冲突字段记录有依据的 `resolution: donor` 或 `latest`。

```sh
python3 scripts/prepare_field_adoption.py request.json adoption.json
```

从 Skill 目录运行；输出文件必须不存在。脚本返回 PREPARED 只表示本地标量合并已生成。若候选摘要等于 latest 摘要，结果为 ALREADY_SATISFIED：记录当前版本已满足所选值，不调用 `timeline-revise` 或提交；本地提交会拒绝 `NO_CHANGE_TO_COMMIT`。只有候选确有变化时，才以 latest 原始 version/document_sha256 调 `timeline-revise`，再以相同 expected_version 提交；提交端会重验。过期后重新读并重算，不能只替换 token。`cross-candidate-01` 是 Agent 构造的操作评估，不代表通用宿主、真实人工修订或局部融合风格效果已通过；该风格仍为 authored-unvalidated。
