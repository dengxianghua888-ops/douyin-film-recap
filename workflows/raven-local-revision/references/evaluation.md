# 局部修改验证

## 必须能证明的行为

- 当前文档及素材版本准确；旧候选不能覆盖新人工编辑。
- 修改只发生在声明范围；全局画幅和源引用不能绕过冻结项。
- “后面不动”的内容与位置分别检查；时长变化导致的位置漂移可见且符合授权。
- 删除锚点后不遗留悬空字幕/音轨；重选素材后字幕/配音重新核对。
- 生成候选不改变当前工程；提交返回当前版本；恢复保留历史且不使旧写入重新有效。
- 最终视频绑定实际渲染版本，不能把新作品和旧QC混用。
- 真实接点视听、表达语义和修改目的完成度另行核验。

## 素材场景

1. 影视：换开头不剧透、保留后段时间；观察前情是否足够、原声是否切断。
2. 口播：删除重复但保护条件；多次手工字幕修正后继续修改。
3. 软件：局部替换新版按钮录像，保留讲解与无关操作；结果窗口同步变化。
4. 跨轮次：先改字幕、再改音量、只撤销字幕；候选出炉后发生新人工改动。
5. 回退：完整版本恢复及局部采用，分别检查内容、音轨、字幕和新版本身份。

测试可用合成媒体证明版本与范围；真实素材可证明执行，但没有完整观看/听检仍不能证明接点自然或表达改善。独立风格评价缺失就保留未验证，不把技术成功率当满意度。

本地SQLite只保证通过本操作提交的状态，不代表原生编辑器实时同步。宿主验收需实际读取手工编辑、操作一次、回读并导出，不能用模拟author=human替代。

## 跨轮次恢复与媒体对照

局部撤销涉及三个角色：历史恢复来源、恢复前最新版本、恢复后新版本。先核对三者身份和素材哈希，把目标字段从来源复制到最新文档；保留后来删除的旁白、修正的字幕和调整的音量。若目标字段后来也被人工改过，比较具体差异并处理冲突，不能用整个历史样式对象无条件覆盖。

验收分开对照：目标字段比历史恢复来源；非目标字段比恢复前最新版本。核对目标字段以外的所有键（包括新增和删除），画面顺序/位置、字幕内容/时间、声音资产/参数分别检查。只改变字幕字号时，应比较紧邻恢复前后的音频 PCM，不用更早的、仍含旁白或不同增益的版本作为声音相等基线。

有损视频不能从工程字段不变推导像素完全不变。先比较提交范围，再比较烧录前画面、无损滤镜输出及最终交付解码帧；字幕外发现差异时记录具体帧，不把抽样相等扩张为整片相等。用户要求逐像素冻结时，当前全片 H.264 重编码路径不能据此通过，需提供能满足该约束的交付策略并单独验收。

声音冻结同样区分参数、编码前 PCM 与最终交付 PCM。比较紧邻修改前后的准确作品版本，并绑定输出采样率、声道顺序、样本格式、时间原点及半开采样区间；原区间/增益相同不代表交付采样相同。`espresso-claims-01` 的共同前 8 秒差异已定位为裁切后重采样的端点效应及 AAC 邻接上下文，见[诊断证据](../../../docs/evidence-scope.md)；历史严格相等失败仍保留。仅调换重采样顺序不能认证 AAC 交付冻结，也不能凭差异大小推断听感变差或听感合格。逐采样冻结必须复用已锁定基线的对应 PCM，在冻结区间不重算采样，采用 PCM/FLAC 等适配容器的无损音频，并对最终交付完整冻结区间逐采样验收；宿主/播放器不支持时显式返回不能满足，不静默退回 AAC。

若用户明确要求字幕区外逐像素冻结，可提供经单独验收的无损母版：固定预字幕源、像素格式、字体文件、ASS 与工具链，分别生成修改前后成片；以源到字幕滤镜参考的真实栅格差异建立字幕掩码，再对两份交付解码后的每一帧、每个 Y/U/V 样本做零容差比较。普通有损 H.264、文档 scope、抽帧、PSNR/SSIM 或“视觉无差异”均不能替代该证据。无损 H.264/FFV1 只在已验收的 codec、container、pix_fmt 与播放器边界内成立，并同时报告体积和兼容性成本。

本地案例 `selective-restore-02`：44号字幕 → 删除独立旁白及关联字幕 → 原声-8改-2dB → 字号恢复30。07→09的完整PCM相同；05→07分段RMS约提升5.959–6.007dB。完整1080帧证据显示05→07画面相同；07→09烧录前画面相同，无损字幕滤镜只改960–1079帧；最终H.264另有24帧差异早于第960帧（最早933），不得声称最终像素严格局限于32–36秒。该案例是Agent执行的版本机制/媒体证据，不能证明旁白删除后故事自足、人工接管或风格效果。证据路径保存在进度账本，原始失败和错误对照报告保留。
