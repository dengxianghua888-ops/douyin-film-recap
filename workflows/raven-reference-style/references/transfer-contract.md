# 迁移矩阵

每个机制包含id、reference_ref及source_interval、evidence_refs、observation_basis、观察事实、解释与不确定性、transfer_rule、target_anchor、target_source_refs、compatible_conditions、decision（adopt/adapt/omit/blocked）、理由、operation_ids、protected_resources和evaluation。

将“前两镜局促，最后见宽景”转成“先限制可见信息，再给目标素材真实支持的空间打开”，不能要求目标拍出参考中的同一人物/地点。把参考音乐当音轨、字体文件当可用字体都需要单独来源及实际使用依据。

共享风格卡只保存可迁移方法和适用边界；项目参考具体路径/时间码保留在作品目录，引用哈希和回执。一次作品的固定timeline与个人长期偏好分开，当前方案不是自动采纳为个人品牌规范。

参考变化、目标素材变化、目标计划变化、LUT/字体变化分别使相关分析/映射/渲染与QC失效。首次hash只建立基线，不认证参考身份或原创性。核对实际采用来源与先前清单；执行后QC绑定当前作品和输出。

无法全量迁移时清楚列出完成维度与受阻维度，不输出“整体同款完成”。用户只要一种局部机制时，不额外复制其他维度；允许合法自有模板与资产复用，权限按实际来源判断，不照搬上游一律禁止复制的绝对政策。

状态类机制须分别满足参考的机制前提和目标的状态/动作支持。任一侧不成立时 decision 为 omit 或 blocked，保留已生成对照及失败原因；不得把排序成功改写为机制迁移成功。调整到更窄机制时作为新声明重新观察和验收，不追认旧实验通过。
