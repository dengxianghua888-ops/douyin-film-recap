# Product and Architecture Decisions

## 1. 任务重新定义

用户口中的“影视混剪”并不是传统音乐驱动 Montage，而是 **Narrated Film Recap**：

```text
解说压缩低价值过程
+ 原片高光承担戏剧、动作、表演和情绪
+ 竖屏、字幕、声音与快节奏编排
```

因此，本项目名称使用 `douyin-film-recap`。纯音乐卡点、跨多部影片意象混剪，应另做上层 Skill，并与本项目共享素材理解和时间线底座。

## 2. 最底层产品矛盾

用户希望：

- 丢入一部长片后自动出片
- 中间几乎不操作
- 结果至少稳定可看
- 高光不能只靠关键词或音量峰值

这意味着系统不能同时把所有判断都交给一次模型生成。它必须：

1. 用模型做内容判断。
2. 用中间状态保留故事与创作决策。
3. 用确定性工具执行时间线。
4. 用门禁阻止“文件生成成功但内容已经坏掉”的假完成。

## 3. 高光为何采用多类型对象

“高光”可能来自：

- 戏剧冲突
- 权力逆转
- 动作完整性
- 关键台词
- 演员表演
- 情绪落点
- 真相揭示
- 悬念
- 喜剧节奏
- 视觉奇观
- 人物选择
- 关系改变

若只训练一个统一高光分，系统会自然偏向大声、快速、视觉刺激，漏掉眼神、反应、停顿和人物选择。

因此，高光对象同时记录：

- 类型
- 故事作用
- 状态变化
- 原声必要性
- 安全边界
- 多维分数
- 剧透、上下文、重复与边界风险
- 选择或淘汰理由

## 4. 为何使用两阶段高光召回

全片逐帧调用强 VLM 成本过高，也不一定更准。

本项目采用：

```text
低成本全量索引
→ 场景信号与语义 Hint 召回
→ Top-K 高密度 filmstrip
→ VLM 复核表演、动作和短视频成立度
```

这既控制成本，也把强模型用在真正需要观察细节的地方。

## 5. 为何维护四条时间轴

影视解说最危险的错误之一，是把“故事发生顺序”和“影片揭示顺序”混为一谈。

本项目维护：

- 原片时间
- 故事实际顺序
- 原片揭示顺序
- 解说输出时间

这使系统能够区分：

- 正常压缩
- 结果前置
- 合理钩子前置
- 不可接受的提前剧透

## 6. 为何先做声音分工，再写 VO

低质量自动解说常见流程是：

```text
先写满旁白
→ 生成 TTS
→ 为了塞下 TTS 强行裁画面和原声
```

本项目先确定每一拍的 `audio_owner`：

- 解说
- 原始对白
- 动作声
- 环境声
- 音乐
- 沉默

再写 VO。旁白是补充信息和连接因果的工具，不是时间线上的暴君。

## 7. “快节奏”如何被翻译

快节奏被拆为：

1. 宏观段落与张力曲线
2. Beat 状态变化
3. 镜头长度与视觉运动
4. VO、原声、动作声和沉默的声音切换

提速优先级：

```text
删除无变化 Beat
→ 压缩重复背景
→ 缩短 VO
→ 晚进早出
→ 替换低价值原片
→ 缩短镜头
→ 最后才提高 TTS 速度
```

## 8. 借鉴关系

### Speclip

借鉴思想：

- 解说推进，原片出刀
- 戏眼优先
- Kill List
- Storyboard 单一真相源

没有复制其代码或文本。

### video-recap-skills

借鉴思想：

- 导演意图和故事计划
- 画面与声音分工
- 原声句界安全
- 阶段产物与 QC 结构

### video-use

借鉴思想：

- 词级时间线
- 切点 padding
- 音频边界淡入淡出
- 输出时间字幕
- 字幕最后烧录
- 有上限的自检

### NarratoAI

借鉴思想：

- ASR、VLM、TTS、字幕和本地部署的完整产品管线
- 多 Provider 与真实兼容性问题
- 从用户反馈中反推时间线、剧情理解和版本回归风险

## 9. 自动化边界

默认无人值守，不要求用户逐步确认。

以下情况必须停止：

- 发布模式但权利未确认
- 人物、事件或时间引用结构性冲突
- 原声被截成残句
- TTS 会被裁尾
- 画面不足以覆盖 VO
- 源时间越界或重复未声明
- 输出缺视频流、音轨、规格错误或黑帧异常

故事与审美模型判断默认只让结果进入 `DEGRADED`，不冒充确定性事实。

## 10. 当前版本真正做到了什么

`0.1.0` 已包括：

- 可安装 CLI 和 Agent Skill
- 字幕优先、ASR 回退
- 镜头检测与视觉索引
- 分层场景与故事理解
- 人物、事件、知识状态
- 多类型高光召回和 VLM 重排
- 自动时长与解说方案
- Storyboard 编译
- TTS 生成和过长文案回压
- 竖屏视频渲染
- 输出时间字幕
- 前后置 QC
- 断点续跑和有限自动修复
- MP4、SRT、EDL、脚本与交付报告

## 11. 尚未伪装成已完成的能力

- 精确人脸身份跟踪
- 多说话人可靠分离
- 专业级智能竖屏运镜
- 自动剪映草稿导出
- 多 Part 批量编排
- 用户参考视频的长期风格学习
- 平台发布与流量闭环
- 版权安全保证

## 12. 下一版优先级

### P0

- 用合法素材做固定回归集
- 评估 Top-K 高光召回与边界完整率
- 补强人物 ID 与相似角色
- 加入成片抽帧语义复核
- 输出更精确的阶段耗时和模型成本

### P1

- 主体跟踪与动态 9:16 构图
- 参考成片 Style Profile
- 剪映 / OTIO 可编辑时间线
- 多 Part 自动拆分
- 用户修改行为记忆

### P2

- 发布后数据回收
- 标题、封面与正文承诺联合优化
- 个人风格的长期偏好模型
