# 排错教学：让每项修复有对应的复验

用于真实异常、代码调试、导出失败、参数冲突和跨服务流程。先把故障分层，再决定删留与叙事；一项修好不等于整个任务完成。

## 故障账本与复验身份

每项记录症状、错误原文、版本与输入、观察证据、原因假设、采用的修改、被排除解释、复验输入及结果。区分：看到了问题、改了代码、重启了服务、某一步通过、全部用户任务完成。修复后的新问题单列，不把第一次错误和最后成功硬拼成单因果。

对跨环节案例分别跟踪：请求受理、计算完成、产物落盘、返回数据、界面呈现、用户取得产物。HTTP200只能支持对应请求状态，页面出现下载链接也不能独立证明文件能打开。播放器存在或时间推进属于视觉观察；声音是否正确仍需实际听检。

已编辑教程里的时钟跳跃、黑场、标签页变化和输入差异是连续性线索。保留这些观察，明确哪些等待/重试已由原作者省略；不能以媒体中的几秒推导真实执行耗时。素材能支持局部修复但缺同条件复验时，保留缺口，继续寻找证据；不要编造成功画面。

## 选段与风格

证据排错以“为什么采取下一步”为主线：保留错误、相关代码或设置、修改与复验，删去无关游走时不能删掉排除假设的依据。失败边界演示则围绕“什么条件下仍会失败”：用相同条件的成功/失败对照定义适用范围。一次偶然故障并不足以支撑通用失败边界。

不能因为找到排错素材就强行同时覆盖两种风格。缺少受控对照时只做证据排错案例，不制造第二个验证结论。要做短版，先明确它是单故障解释还是完整排错链；不靠删除后续故障把长链伪装成一招修复。

结果预览可提前，但须清楚标示，并在后续回到真实起点。动态状态面板应按证据更新：修改完成可以写“已修改，待复验”，不能提前勾选“已解决”。重复出现的相同报错需要判断是否是旧终端残留，不能把屏幕上还在的旧日志当成新失败。

对持续多秒的提示，分别检查入点和出点的状态。入点只有下载目录、稍后才出现播放器时，应写“继续打开并试听”，不能因为段末出现了播放器就把整段标成“已经打开”。这是 AudioGen 排错样片实际抽帧发现的修订项，不要求所有教程套用固定八秒窗口。

## 源码补研与可读性

从作者配套链接固定提交、文件哈希及许可。仓库最终分支可能与录屏中的中间版本不同：出现文件缺失或代码不一致时记录差异，不把最终源码覆盖原来的错误过程。库函数的参数语义可以辅助解释假设，但源码静读不能替代当时实际调用与结果。

关键错误信息、文件名、返回字段和修改行需要在最终输出尺寸下可辨认。可使用有来源的代码节选、明确放大或附图；保留周边身份和错误上下文。避免整屏文字缩得过小，同时也避免只放大一行丢失它属于哪个文件/哪个请求。

## 采集工具的采用边界

精读并核验的两份采集实现见[采集来源锁](../../../provenance/tutorial-capture-sources.lock.json)。借鉴动作事件与媒体分开记录、场景级恢复、原始录制到剪后时间映射。当前尚未接入新录制原子，不能把文档研究计为采集能力可用。

- 浮层光标和点击波纹是可视化，不是操作成功凭据。事件可能记录在真实动作前或后，要声明记录点；点击失败必须进入结果与失败状态。
- 捕获脚本可能吞掉点击/输入异常后仍输出视频；文件存在不足以证明流程成功，必须读每步结果并回看实际界面。
- `skipWhile` 等删等待机制需要保留删减映射，不能只交剪后时长。系统时钟与视频起点近似同步的精度也要核准，不能直接当帧级真值。
- 为演示注入的浮层、隐藏的工具栏和脱敏改动单独列出。不要把经界面修改的录制宣称完全原样，也不能隐藏承担诊断作用的错误/开发状态。
- 不复用清空既有录制目录、静默覆盖输出或默认复用个人登录资料的行为。复用已授权目标与独立工作目录，失败恢复定位未完成阶段。

研究未执行上游采集器，不报告其稳定性或效果排名。


## 受控参数修复：从相同输入比较单项改变

先写明用户目标，再判定结果是否失败。miniPaint 4.14.3 本例的目标是“宽600并保持原图3:2比例”：同时显式填写宽600、高800得到600×800，只是设置与目标不符，不是软件崩溃或普遍缺陷。若目标就是固定宽高，该参数可能合理。

采用“固定版本和输入 → A重复 → 恢复原图 → 只变一项 → B复验 → 保存重开”链路。保存A1/A2与恢复起点的实际工程，核对内嵌像素，而不是仅对比截图。记录所有表单值、算法及图层范围；本例只有Height从800改为空，其余控件一致。A1/A2像素相同、恢复起点与原图相同、B与重新打开后的图像相同，结论仅覆盖这一输入和版本。完整[案例来源](../../../provenance/minipaint-diagnosis-reference.json)。

字段值与占位符必须区分：Height清空后仍显示浅灰800，不能把它读成实填值。Information可能在鼠标移动后才刷新，要保留真实刷新动作并和已保存文件交叉核对；图上印刷的1200×800不是当前尺寸元数据。动作事件主机时间与媒体时间近似相关，提示入点须看实际输出帧，不能直接把事件时钟当帧级真值。

诊断版保留重复、重置、修改、复验的因果依据；对比版可省略重复和等待，但必须说明省略，并使用同输入、同算法、同展示尺度比较实际输出。比较板保留各图真实宽高比，不把变形图压回同一框造成假一致。条件选择优于无条件优胜：保持比例时本例清空高度；需要明确固定宽高时另行接受比例变化。两版剪后时长不用于推断操作效率。


## 跨输入适用边界与判断依据

上述修复不能变成“所有缩放都要清空高度”。追加三张原创校准图、七个预声明条件，真实UI逐案执行并回读14份保存/重开工程；[边界案例来源](../../../provenance/minipaint-boundary-reference.json)绑定完整记录。

| 输入与参数 | 实际结果 | 教程应解释什么 |
|---|---|---|
| 800×1200，宽600、高空 | 600×900 | 竖图也按原始比例推导；不能直接套横图的400高度 |
| 1001×667，宽600、高空 | 600×400 | 像素取整；高的未取整值约399.80，比例相对误差约0.05%，不能说数学比例严格相等 |
| 1001×667，宽空、高300 | 450×300 | 仅指定高度也可推导宽度；教程规则不必固定成只填宽度 |
| 513×513，宽257、高空 | 257×257 | 正方形保持正方形，不凭默认占位符猜当前值 |
| 800×1200，明确600×800 | 600×800 | 明确接受变形的尺寸目标达成；若同时要求不变形，需另定裁切/留边策略，当前案例未验证这些策略 |
| 1001×667，宽600、高空、两个百分比50 | 600×400 | 本版本像素尺寸参与时，本例百分比未决定结果；不要凭“填了50%”讲成缩小一半，示范应只用一套单位 |
| 800×1200，所有尺寸字段留空 | 800×1200，像素未变且提示缺尺寸 | 点击Ok返回、对话框消失不等于缩放成功；错误提示与文件状态一起决定结果 |

以上全为单栅格图层、All、Lanczos，未覆盖Active、多图层、矢量、文字或其他软件。像素推导属于可测操作；“尺寸达标是否符合用户目标”由复杂层判断。把尺寸、比例/形状、裁切范围分开验，不以单一数字盖过意图。

本次实际截图还显示：部分竖图/方图在右上角Preview缩略图里圆形被压扁，而主画布与保存文件保持正常。教程应指明主画布、图层/画布尺寸及导出文件各自证明什么；出现不一致时先核对实际产物，不把缩略图误差当成图像变形，也不宣布应用全面无错。这是本版本观察，未修改或全面诊断上游应用。
