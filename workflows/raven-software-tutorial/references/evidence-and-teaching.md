# 操作证据与教学判断

## 一次完整的学习动作

每步包含：用户目的、入口/前提、动作对象、动作、可观察结果与验证。目的不必每次重念，入口可以在前一步建立；但导出文件、提交任务、启动处理、处理完成是不同状态，不因“导出成功”文案先写好了就提前显示。

选段保留动作发生前可定位的界面，动作后留反馈和足够阅读窗口。复杂菜单要保留路径；简单重复操作可压缩，只要观众知道省略了什么。决定等待是否可删时检查等待中的进度、错误、权限反馈是否承担教学信息；删等待需提示省略，不据剪后时间作性能承诺。

## 叙事与连续性

- 初学教程按照真实依赖排序；有经验观众的技巧卡可省略通用入口，但必须保留适用版本与必要设置。
- 先展示结果是允许的叙事策略，标为预览，随后回到初始状态；不要让预览混入执行证据。
- 前后对比用同一输入和口径，若账号/数据/条件不同须说明。不把不同 take 的不兼容设置剪成一次成功。
- 错误修复要保留错误码/症状、诊断选择和复验；不把重启碰巧有效剪成确定根因。
- 生成、排队、导出、保存、发布逐项区分；本片需要证明哪一步，就实际呈现哪一步的证据。

## 画面与声音

先看实际输出尺寸下的最小必要文字，再决定全景与放大。聚焦框应包括按钮及它作用的对象；结果出现别马上切掉。相邻同屏焦点切换保留定位锚点，不能让光标突然跳到无关位置。高亮只用于当前一步，不把整个画面框满。

旁白若说“点击这里”，当前画面必须明确这里是哪；能说清按钮名就不要依赖含糊指代。预测结果、讲解动作、确认结果三种语态对应不同时间位置。不要用完成音效提前宣告排队中的任务已完成。

屏幕文字很多时降低字幕密度；操作说明卡不必逐字照抄旁白，真正字幕必须忠实于声音。图示只解释机制，不作为真实 UI 或性能证据。可读性、观察时间由目标观众与内容密度决定，不用一个固定秒数套所有屏幕。

## 资料与权限边界

复用用户已授权素材；展示数据使用可公开或已授权内容。需要脱敏时不能把框选当遮挡，最终输出复核才证明遮挡生效。录制不可逆外部操作按实际授权处理；制作教程本身不自动授权付款、发布或发送消息。

缺录屏时可以写拍摄清单和旁白草案；完整制作任务仍保留未完成状态。合成 UI、重演、截图动画必须说明类型。来源方法见 [融合记录](../../../provenance/fusion-tutorial.md)。
