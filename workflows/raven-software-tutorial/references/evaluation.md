# 软件教程评测与风格组合

## 分开六类证据

1. 编译合同：源身份、事件完整性、帧量化、依赖顺序、结果提示时序。合成媒体测试证明运算，不证明实际产品行为。
2. 操作真实性：逐个对照源录像，按钮/输入/结果对应，同一案例状态一致。只看日志或截图不等于检查过连续动作。
3. 教学复现：按目标受众基础，在相同版本和给定初始条件下完成任务；记录卡住的位置及原因。制作人自己的“看懂”不能代替独立新手复现。
4. 最终视听：实际最终文件，确认最小文字、焦点、字幕遮挡、语音同步、音量与结果阅读窗口。
5. 风格效果：同一任务素材分别使用不同机制，判断哪些信息被前置/保留、节奏在哪变化、观看目标是否达成。
6. 宿主工程：需要可编辑项目时，在目标软件内打开、修改、再导出；本库 JSON 通过不能代替。

任何关键步骤错误、结果造假、漏必要条件都不能被高审美分抵消。技术 PASSED + 视听/真实任务未验收 = 交付 DEGRADED。

## 首批评测素材

- 简单可逆任务：创建对象、修改属性、保存/导出并验证结果。
- 复杂多步骤任务：包含前置设置、异步等待、结果检查；覆盖多次焦点移动。
- 问题修复任务：有真实错误、一次有根据的诊断、修复及同条件复验。
- 文字密集/横转竖：表格或编辑器，验证结果与入口不会被裁掉。
- 已有配音锁定、无配音静音教程、更新版本后的局部修订。

素材与检查方法没有就标 NOT_RUN；不自动把合成录屏加入真实素材通过数量。

## 风格组合规则

选一个叙事主轴：操作教学、问题诊断、条件对比或产品价值；节奏、声音、视觉可局部借用其他卡。静音操作可搭新手教学，但需要文字替代必需说明；结果预览可搭完整教学，但必须标示回到起点。证据型演示不能叠加未经证明的提速数字，快速技巧也不能省掉触发条件。

对照先比较目标相同的近邻，例如“逐步带练”与“问题解决”，区别在前者展示操作依赖、后者保留诊断路径。若同素材无法显现差异，就合并规则或换更合适的素材，不靠不同字体、LUT 和背景音乐凑风格。

每个风格记录独立验证状态、素材哈希、版本、差异、缺陷与修订原因；新增卡不自动进入首发已验证范围。独立评审不可用时明确单人或制作人自评。

这只提供一例真实历史素材的诊断表达与局部修订证据。完整视听、首尾声音、原英文讲解与新增中文提示的连续阅读负担、独立学习效果、同条件故障复现、多风格对照和目标编辑器均未验收；风格仍authored-unvalidated。下一步先用当前可重现且版本明确的任务检验缺省状态/保存/重新打开，再与证据排错进行有意义的教学组织对照；不可把多处历史修改后的成功当作受控因果实验。
