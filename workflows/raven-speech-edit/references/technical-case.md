# 技术案例：保留决策链与数字口径

处理技术分享、项目复盘或“把这个方案怎么改好的讲清楚”时读取。适配[案例复盘](../../../styles/speech/case-reconstruction.md)、[证据解释](../../../styles/speech/evidence-led.md)和[问题到解决](../../../styles/speech/problem-solution.md)。技术分享里有代码截图，不等于素材具备可跟做教程的全部操作。

## 先还原当时为什么这样做

在内容稿中标出目标、当时已知信息、最初尝试、暴露的问题、改变的假设、后续方法和结果。简报可用来核对术语与章节；原话里的迟疑、限制和口头补充仍回到音轨，不拿简报替代逐字稿。

本库记录的 COSCUP 案例涉及检索策略、请求数量与匹配核验三个不同问题。复盘时分别登记待解决问题、方案变化和未核准部分，再决定哪些源范围需要保留。下面只列数值口径与本库的表达约束，不重刊讲义叙述或把历史案例写成本轮新实测。

原话使用“后来”“所以”“这个方案”时，检查前置对象是否仍在。没有可靠声学边界的阶段可保留连续段落形成审阅候选，不能把模型合法时间戳升级成可无痕剪辑的接点。保留的长段应仍有明确内容目的；持续补核准依据，而非用保留全片回避剪辑。

## 数字必须与指标一起保留

为每个核心数字记录值、单位、对象、时间、获得方式和适用范围，并注明源话、简报或新测量的身份。不同指标不能跨口径换算。

| 原证据 | 可表达内容 | 不成立的改写 |
|---|---|---|
| 约7,000条记录、5种搜索组合 | 该策略约产生3.5万次查询，记录数仍增长 | 已实测3.5万次、固定永久只有7,000条 |
| 简报称批量查询1次 | 描述的查询步骤改为一次批量请求 | 全部数据整合只需1次请求 |
| 查询次数减少 | 请求次数的变化 | 速度提升35,000倍、成本同倍下降 |
| 只有一条搜索结果，推测对应 | 单结果启发式与其不确定性 | 匹配准确率100% |
| 讲者展示结果表截图 | 讲者展示的历史结果/界面 | Agent本轮已运行查询、结果仍最新 |

不通过夸张大字、计时器或快速进度动画暗示没有测量的速度。需要性能结论时，另建相同输入、环境与指标的运行对照；这属于新增实测，不伪装成原素材事实。

## 解释与阅读画面

现场画面保留讲者、指向和场景；证据阅读画面优先保留表头、单位、限定、上下文标签及来源。摄像机拍摄的投影存在透视、曝光和分辨率限制。矩形放大不能恢复模糊文字，也不能称为取得原始录屏。

先核对实际源帧与简报，确定裁切范围后调用[screen-focus](../../../atomic/screen-focus/SKILL.md)。记录原源范围、派生源范围、矩形、尺寸及回执；派生画面重新绑定哈希。不要让新的零起点派生文件失去原片时间映射。基于当前版本用[work-variant-create](../../../atomic/work-variant-create/SKILL.md)保留上下文亲代，以便对照、恢复和后续手改。

裁掉人物是表达取舍。依赖表情、手势或问答互动的段落不宜全程聚焦投影；数字和代码截图较密时可以切换阅读画面。实际放大后仍不可读，应调整输出形式或取得许可清楚的资料，不凭“像素更大”判合格。源简报里的第三方插图也要保留独立来源边界。

### 模糊代码的替代方式

先找讲者原链接、原文件或对应版本；不要从糊字猜补可执行代码。取得仓库时固定提交，核对许可证、文件 Git 对象和本地 SHA-256；仅下载阅读不等于已经安装或执行。演讲前提交只是时间上相符，不能据此声称与屏内代码逐字相同；有差异或无法核准时标为“仓库参考”，保留原页与匹配边界。

根据解释目的选择核心行，保持文字字面与源码一致，注明节选；完整代码和许可可作为附件。十秒左右的窗口不应硬塞几十行让观众读完。裁剪或换行不得隐藏必需条件、把可选字段写成必有值，也不能给片段套上“可直接运行”的承诺。版本、来源、节选/完整和是否实测是观众判断信息性质所需的内容，应在画面或交付资料中可查。

图卡出现范围由实际源画面与解释内容核对，不能按简报顺序假设演讲没有回翻。替换解释层在同一作品提交，主轨、原声、未改字幕和亲代保持；输出检查进出前后、最小字与完整边界。字清楚与九秒内理解充分是不同验收项，仍需实际观看。新图卡不能掩盖原先未核准的首尾声音。

## 验证范围

检查删改后决策是否可理解、数值是否保留口径、结果是否被夸大、原话/简报/实测身份是否混淆。完整试听检查首尾和跨段指代，实际查看阅读版边界及中间画面。文件可解码、派生哈希正确或原子执行成功，均不证明以上内容效果。
