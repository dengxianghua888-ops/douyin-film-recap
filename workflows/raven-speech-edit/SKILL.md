# 口播与知识表达

本文件中已标识的 duyi 改写段落按[材料级来源与修改通知](../../provenance/distribution-notices/speech-text-NOTICE.md)及其中覆盖表保留署名、许可和非商业条件；该范围不扩展为软件、其他来源或全库许可。

先读 [共享合同](../../contracts/editorial-contract.md)。当前是有本地执行依赖的试验版，真实口播效果尚未验收。以已有原视频、准确转写和当前作品为工作对象，不将人物说过的话改成 Agent 自己的观点。

## 明确本次表达任务

区分：清理口误/重复、保留观点的缩短、提取独立知识段、重构论证、加字幕/声音/画面包装或基于旧版局部修改。只要求字幕时不顺带美颜、加音乐或改时序。只有清理时，默认不改变论证顺序或表达立场；用户明确要求重构时再做语义重排。

记录受众已有知识、核心问题、目标长度、必须保留的限定/例子/原句、语气和禁止修改项。平台只是交付约束，不自动意味着快剪、花字或夸张钩子。

正式发言或带烧录字幕/外部原稿的素材，按[正式发言与原稿协议](references/prepared-statements.md)区分完整留档、专题节选和行动主体清单；按实际需要加载对应风格。段落范围明确时可直接建立可编辑段落试剪，不制造逐词稿来适配接口；词内精剪仍须满足逐词与声学合同。

## 1. 素材和转写

用 [media-inspect](../../atomic/media-inspect/SKILL.md) 核对源身份。对已有逐词稿调用 [transcript-import](../../atomic/transcript-import/SKILL.md)；文本、音轨和版本绑定。没有可靠逐词时间时可以做内容建议，但不可生成虚构毫秒切点。可在已核验本地环境中调用[speech-transcribe-local](../../atomic/speech-transcribe-local/SKILL.md)，显式给定语言、音轨和源窗口；先读[ASR观察与来源融合](references/asr-observation.md)。这是模型候选而非已听检稿；云Provider和独立强制对齐未接入，不能将macOS TTS当识别工具。

有用户稿或独立参考时，用[transcript-reference-compare](../../atomic/transcript-reference-compare/SKILL.md)锁定原文件、字段选择、素材范围与版本，形成字符差异清单；对照无差异也不代表声音已核实。差异的纠正与重要性由本层回源判断，保留旧稿并为更正稿创建新版本；不能把参考稿的字直接套用模型时间。

阅读全文建立“观点→论据→例子→条件→结论”结构，再局部判断删改。“去重复/选最好一遍”先读[句中修正与独立重录](references/repairs-and-retakes.md)，区分启动残句、主语/条件修正、解释性重复和真正多take；相似文字不等于等价尝试。多 take 比较完整性、表达自然度、语义一致和原上下文位置；后来更流畅的一遍不一定能搬到前面。

技术分享或项目复盘按[技术案例与数字口径](references/technical-case.md)保留最初尝试、遇到的问题和改变方法的理由。简报不是逐字稿，查询次数不是运行速度，结果截图不是本轮实际操作；要做录屏跟做时另核对素材是否包含完整操作和验证步骤。

## 2. 选择表达风格

读 [风格索引](../../styles/speech/index.md)，按教学/观点/经验/情绪等目标加载具体卡。个人表达、团队品牌、平台规格分别记录；不让“品牌干练”覆盖说话者刻意的犹豫或限定。

自然、紧凑、犀利、陪伴等词先落实到选段、结构、例子、停顿和声音规则。风格不会授权改写说话者原声。要新旁白或重录，列为单独用户意图，不能字幕润色后假装原话已改变。

## 3. 语义选择

按 [语义与声学规则](references/semantic-editing.md) 区分纯填充、语气词、重复 take、自我修正、必要限定和有意停顿。保留理由和删除理由都绑定 word_id 与源范围。把否定、条件、数值单位、比较对象、引用归属和例外写入保护项。

需要跨轮保持的保护按[作品合同](../../contracts/work-contract.md)登记为当前版本的 evidence_protection。普通缩短不能连保护声明一起删去；时序变化只显式更新允许的映射并重验覆盖。修改保护依据属于独立决定，不能为了达到时长自动撤销；词界不可靠时先保留完整句/段落，技术覆盖通过不代替语义和声音复核。

形成删改后的可读全文，检查主语/指代、条件范围、因果、观点强度和例子对应关系。不要以删除率、成片更短或每分钟切点数作为质量目标。风格卡相同也应尊重不同说话者的节奏。

## 4. 声学边界与编译

模型词时间不足时先读[中文独立对齐](references/chinese-alignment.md)。已有CTC、Qwen短录音及连续口播研究证据，但未形成正式可剪对齐原子。Qwen在同一文字的不同音频窗口下会改变边界；不能选一组结构合法的时间就当成已核准。先核准文字和整句范围，再验证需要细剪的接点；不让研究候选直接进入逐词编译。

逐个复核删除后接点，记录真实边界证据：原声起止、爆破音/尾音、气口、重叠说话人、手势和视线。区间覆盖保留词且不带回被删词；没有足够空间时保留该词、删除完整残句或选择其他 take，不能为满足删词清单硬剪。

调用 [speech-plan-compile](../../atomic/speech-plan-compile/SKILL.md) 提交连续词 ID、明确切点和保护项。编译器只算时间，不替你判断废话。拒绝信息回到对应决策处理，不放宽校验掩盖残音或语义损坏。

新作品将确定计划登记到[work-version](../../atomic/work-version/SKILL.md)，用[work-render](../../atomic/work-render/SKILL.md)从同一当前作品导出；独立计划试验可用[timeline-render](../../atomic/timeline-render/SKILL.md)。字幕按新的输出时间映射。先决定有完整语义的字幕分组，再调用 [caption-map](../../atomic/caption-map/SKILL.md)；逐词数据不能直接等同逐字闪字幕。字幕样式明确后可调用 [caption-burn](../../atomic/caption-burn/SKILL.md)。

## 5. 包装与声音

仅在帮助解释、证据展示或节奏时添加 B-roll/动效，不能用随机漂亮素材掩盖主讲者表达。图表/数据要有来源，画面不得暗示未说过的结论。需要时按[解释画面协议](references/explanatory-layers.md)选择素材、时机和布局，再用[视频叠层原子](../../atomic/visual-layer-render/SKILL.md)进入同一作品。本库本地原子支持显式静态矩形视频叠层；MG 与跟踪须核当前 Agent 工具，未具备时保留缺项。最终可读性与遮挡须查看输出。

已有音频通过 [audio-mix](../../atomic/audio-mix/SKILL.md) 按明确增益和窗口摆放；人声可懂优先。窗口决定由复杂层给出，不能把整片压低声量当作完成避让。原声口播通常无须 TTS。

## 6. 验收、修改与交付

按 [评测规则](references/evaluation.md) 对本次最终文件核对残字、含义、同步、字幕和听感。只有技术检查用 [media-qc](../../atomic/media-qc/SKILL.md)；缺全片声音复核不能 PASSED。

REVISION 从当前稿和工程继续；只改已授权对象，保留人工修正。读取当前work-version并用[timeline-revise](../../atomic/timeline-revise/SKILL.md)提交明确scope的候选；语义重剪更新词选择并重编译后，将结果并回同一作品再commit／render，不能另建一份孤立计划覆盖人工字幕。需要风格对照时用[work-variant-create](../../atomic/work-variant-create/SKILL.md)派生独立版本并保护父版。timeline-patch只用于明确的独立计划调整，不替代当前作品提交。字幕源稿、配音稿、输出字幕、时间线不混为一个权威对象。

交付保留稿、删改差异及理由、源/输出映射、实际视频/字幕和检查证据。JSON 片段表可再编辑，但不是已经验收的原生编辑器工程。未完成 ASR、B-roll、宿主或听检时精确说明该部分状态。
