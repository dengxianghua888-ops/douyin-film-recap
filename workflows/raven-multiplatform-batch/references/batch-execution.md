# 固定计划与恢复

先按本次模式逐版读取最新状态，确认实际依赖、来源/修订、输出目标与授权范围。需要执行时由Agent使用实际队列/导出工具，记录原任务ID、工具身份、每项输入/产物和终态；成功仅在实际输出仍与目标版本绑定且核验通过后复用。超时、取消或部分结果先查询原任务并读回同作修订、目标与非目标，区分已应用/未应用/部分/未知；尚可能继续写入时不启动竞争任务，也不盲重放。无安全并发或必要读回只阻塞该写入/恢复，可按原授权交未采用的隔离候选；不能强制改存储格式。具体读回条件遵循[通用能力交接](../../../contracts/capability-handoff.md)。

以下prepare、manifest、SQLite、OS锁及retry_failed是**选择本库本地work-batch-render后的严格实现规则**，不套给其他工具。用prepare固定store/version/document与运行时／工具字节。manifest是不可变指令，SQLite是可恢复任务索引，render尝试目录保留最终回执和所有产物。三者作用不同。prepare成功不等于导出；status不重验输出；run的RENDERED不等于创作验收。

同一batch只允许一个活worker。不要根据超时、控制进程退出或旧日志判断真实子进程死亡：OS锁包含本地子工具生命周期。忙时返回BATCH_BUSY，等待真实退出后再恢复，禁止删锁文件抢跑。局部失败不停止其他独立项；一次run每选中项最多一个新尝试。未获得最终回执的旧尝试保留INTERRUPTED，不覆盖；完整合法回执恢复索引即可。

retry_failed=true明确允许本地失败项本次重试，成功项依旧校验复用。源文件修复要与原manifest／文档哈希一致，输入实质改变则新版本新batch。已完成输出损坏需标INVALID_OUTPUT，不能仅更新hash自证。收费服务与远端发布不在此队列能力内，不能把本地重试规则套成远端无条件重提。
