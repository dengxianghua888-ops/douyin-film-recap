# 高光召回与事件完整性

全量素材索引、候选召回、事件判断、成片选择是四个不同结果。声音大、画面变化大、弹幕密集、比分变化都可能是线索，不能单独证明精彩。游戏读提示很吵可能没有事件；安静残局或小球快速入网可能很重要。

## 两轮观察

第一轮按全部素材分块：逐帧变化测量、音频窗口、现有转写/日志、场景概览。记录实际PTS覆盖及空缺，音视频分别报告。块边界至少有足以检查切断事件的重叠，重叠时保留来源身份防止双计；不把所有领域统一为固定五秒前后。

第二轮回到候选：向前找参与者、目标、空间和规则，向后看动作结果与确认。密集抽帧和连续播放互补；观察到传球不等于助攻、球接近篮筐不等于进球。结果未入镜、裁判未确认或素材提前结束，标未知/open。事件虽有动作结束也未必有比赛结果，二者分开。

测量使用低分辨率只是信号索引。小物体、快速字幕、比分角标必须在原始分辨率回看，必要时明确裁出已有坐标区间观察，不用生成画面补证据。固定1fps很容易漏掉单帧或短动作；但逐帧差也会漏掉缓慢战略变化，不声称解决全部召回。

## 事件图与回放

每个真实事件一个canonical ID；原始发生、广播回放、创作回放为不同呈现实例。判同一性看动作、参赛者、场地、时钟/比分和来源日志，不看文件是否不同。同一动作换角度不算第二次成功。

setup/action/outcome划分由复杂层声明，明确哪些必须保留。为了高光开头前置结果可作为清晰标记的预告结构处理，当前event-plan-compile只支持主事件后回放；不能伪造普通primary顺序绕过这个限制。需要更复杂结构时扩展明确合同后实现。

## 反应、字幕与声音

观众或主播反应须与事件同期或明确说明是后续回顾，不能移植尖叫来提高刺激。虚构台词、伪造弹幕、把无声源配成现场欢呼都不允许。生成音效可作为创作包装，但不冒充原声音证据。

每个风格决定列出“改变哪些镜头/段落/声音”而非只标情绪词；同素材对照时保留用户要求的事实与事件身份。未选中的事件记录原因，区分内容不适用与未观察/能力缺失。
